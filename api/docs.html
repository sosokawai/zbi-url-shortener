zbi.babby api

For bots, scripts and anything that speaks http.

Nothing is stored. A short link is the original link, compressed into the address itself, so shorten and expand are pure functions of their input. No database, no accounts, no rate limit, no expiry and nothing to leak.

Links come in two flavours: #fragment links, which are unpacked in your browser, and /path links (mode=qr), which the site reads from the path and which are therefore safe to print as a QR code.

Endpoints

  

    

      Method
      Path
      Description
    

    

      GET, POST
      /api/v1/shorten
      Compress a link. Parameters: url (required), mode = hash, emoji or qr.
    

    

      GET
      /api/v1/expand
      Unpack a short link. Parameter: link (a full short link, or a bare payload).
    

    

      GET
      /api/v1/health
      Liveness check.
    

    

      GET
      /api/v1
      This list, as JSON.
    

  


  
Shorten

  
# json in, json out, which is what curl gets
curl -G "https://zbi.babby/api/v1/shorten" \
  --data-urlencode "url=https://www.amazon.com/dp/B0CX23V2ZK/ref=sr_1_1?keywords=widget&qid=1720000000"

# the --data-urlencode is what keeps the ? and & in the link from being read
# as parameters of the api call itself

# one line of text instead of json, for bots
curl -G "https://zbi.babby/api/v1/shorten" --data-urlencode "url=https://example.com/x" -d "format=text"
curl -H "Accept: text/plain" "https://zbi.babby/api/v1/shorten?url=https://example.com/x"

# post it instead, as json
curl -X POST https://zbi.babby/api/v1/shorten \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/some/long/path","mode":"hash"}'

# or as a form, the way a html form would send it
curl -X POST https://zbi.babby/api/v1/shorten -d "url=https://example.com/x"

# qr links keep the payload in the path
curl -G "https://zbi.babby/api/v1/shorten" --data-urlencode "url=https://example.com/x" -d "mode=qr" -d "format=text"

Expand

  
# percent-encode the # so it is not read as a fragment of the api call
curl "https://zbi.babby/api/v1/expand?link=https%3A%2F%2Fzbi.babby%23j%2C7*%2BlgC%23nlHXCWK7%23Bs!%2BZxT*GtbviRyo_Zl%40C*%2F%3Ff%40IA$0%5BwM%27Tj%26%21"

# or let curl do it
curl -G "https://zbi.babby/api/v1/expand" \
  --data-urlencode "link=https://zbi.babby#j,7*+lgC#nlHXCWK7#Bs!+ZxT*GtbviRyo_Zl@C*/?f@IA$0[wM'Tj&!"

# a bare payload works too
curl -G "https://zbi.babby/api/v1/expand" --data-urlencode "payload=OQ/ap#"


  
Response:

  
{ "url": "https://www.amazon.com/dp/B0CX23V2ZK/ref=sr_1_1?keywords=widget&qid=1720000000" }


  
Errors

{
  "error": {
    "code": "unsupported_protocol",
    "message": "Only http and https links can be compressed, got \"ftp:\"."
  }

Rules

  
    
    
  • only http and https links, and no credentials in the URL
    • 
    
  • links are capped at 2048 characters, see MAX_URL_LENGTH
    • 
    
  • CORS is open, so a script on any page may call it
    • 
    
  • format=text or Accept: text/plain returns bare text instead of JSON
    • 
    
  • nothing is written down, and no link is ever logged
    •
